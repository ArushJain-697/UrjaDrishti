
data_loader.py
load_data(path)
Reads the CSV from disk using pandas, parsing the timestamp column directly into datetime objects during the read so no separate conversion step is needed later. It then sorts the entire DataFrame chronologically by timestamp and resets the integer index so the index is a clean 0-to-N sequence. Returns the raw DataFrame ready for splitting.
temporal_split(df, calib_months=3, val_months=2, test_months=2)
Takes the full DataFrame and carves it into four non-overlapping chronological windows. It finds the maximum timestamp in the data and works backwards to place the boundaries. The test window occupies the final two months. The validation window occupies the two months immediately before that. The calibration window occupies the three months before validation. Everything before calibration becomes the training set.
The reason for working backwards from the maximum timestamp rather than forwards from the minimum is that you always want the test set to be the most recent data, which is the hardest to forecast and the most representative of real deployment conditions.
Training is the longest window because the Stage-1 model needs as much historical data as possible to learn plant behaviour, weather patterns, and seasonal cycles. Calibration is a dedicated held-out set that Stage-1 has never seen during fitting — MAPIE uses it to compute the conformity scores that determine how wide the P10-P90 intervals need to be to achieve 80% empirical coverage. Validation is used for LightGBM early stopping in Stage-1 and as the source of realistic Stage-1 errors for Stage-2 training. Test is the final benchmark that nothing touches until evaluation.
After computing the four subsets it prints the row counts and the date ranges of each split, then returns all four DataFrames.

feature_engineering.py
Module-level constants
_ID_COLS lists the columns that identify a row but are not model inputs: timestamp, plant_id, and cluster_id. _TARGET is the name of the column containing the ground truth generation in MW. _CAT_MAP maps the string plant types solar and wind to integers 0 and 1. FEATURE_COLS is the authoritative ordered list of the 17 columns the model actually receives.
transform(df)
This is the single function that converts a raw DataFrame into the arrays the model can consume. It makes a copy of the input to avoid mutating the caller's data. It creates the plant_type_enc column by mapping the string plant_type column through _CAT_MAP, filling any unmapped values with -1, and casting to integer. It then selects only the 17 columns listed in FEATURE_COLS to form X. If the target column actual_generation_mw is present in the DataFrame, it extracts it as y; otherwise y is None. This None branch is used at inference time when you have features but no actuals yet. Returns the tuple (X, y).
get_feature_names()
A utility that returns a copy of the FEATURE_COLS list. It exists so other modules can inspect the feature set without importing the private constant directly. Used for introspection and for building single-row DataFrames in Stage-2 inference.

model.py
Module-level constants
_BASE_PARAMS is a dictionary of LightGBM hyperparameters shared by both Stage-1 and Stage-2 models. Five hundred trees, a modest learning rate of 0.05, 63 leaves per tree which is enough complexity to capture non-linear interactions without being so deep that the tree memorises noise, minimum 20 samples per leaf to prevent very specific splits, 80% row subsampling and 80% column subsampling per tree to reduce overfitting, a fixed random seed for reproducibility, and -1 for n_jobs meaning use all available CPU cores. _CALLBACKS is a list of two LightGBM callbacks: one that halts training when the validation metric has not improved for 50 consecutive trees (early stopping), and one that prints the current metric to stdout every 100 trees.
_STAGE2_FEATURES is the ordered list of the 10 features the Stage-2 corrector model uses. It is defined at module level so it serves as the single source of truth for both training (in build_stage2_training_data) and inference (in predict_stage2).
train_stage1(X_train, y_train, X_calib, y_calib, X_val, y_val)
This function builds and calibrates the Stage-1 forecasting model. The first step is training a base LightGBM regressor. It instantiates lgb.LGBMRegressor with the shared _BASE_PARAMS and calls .fit() with the training data. The eval_set argument provides the validation data so LightGBM can track out-of-sample performance, and the _CALLBACKS list supplies the early stopping and logging behaviour. At this point the base model is a standard point-forecast regressor that predicts MW generation but has no concept of uncertainty.
The second step wraps that fitted base model inside a MapieQuantileRegressor. MAPIE stands for Model Agnostic Prediction Interval Estimator. The arguments are: the already-fitted base estimator, method="quantile" to use conformalized quantile regression, cv="split" to signal that you will supply an external calibration set rather than using cross-validation, and alpha=0.2 which targets 80% coverage meaning the interval from P10 to P90 should contain the actual value approximately 80% of the time.
The MAPIE .fit() call receives the training data again and additionally X_calib and y_calib. What MAPIE does internally during this calibration step is: it asks the base model to predict on the calibration set, computes the signed residuals between predictions and actuals at the desired quantile levels, and finds the conformity scores that need to be added to the raw quantile predictions to guarantee the coverage property on new data. This is the conformal calibration step that turns uncalibrated quantile predictions into statistically valid prediction intervals.
The fitted mapie object is returned. It stores the base LightGBM model internally and carries the calibration information needed to produce intervals at inference time.
predict_stage1(mapie_model, X, return_pis=False)
Calls MAPIE's .predict() method on the feature matrix X. MAPIE always returns two objects: y_pred, a 1D array of P50 point forecasts, and y_pis, a 3D array of shape (n_samples, 2, 1) where the second dimension contains the lower bound and upper bound of the interval. The function immediately squeezes y_pis into two 1D arrays called p10 and p90.
If return_pis is False it returns only y_pred. This is the default and is used everywhere Stage-2 training code calls this function, because Stage-2 only needs the point forecast to compute residuals. If return_pis is True it returns the tuple (y_pred, p10, p90). This is used by evaluate_coverage in main.py and by get_forecast when assembling the final uncertainty-aware output. The flag exists to preserve backward compatibility with all existing code that expects a single array from this function.
build_stage2_training_data(df_with_s1_pred)
This is the most computationally intensive function in the codebase. Its job is to create the training dataset for the Stage-2 corrector by simulating every possible intra-day recalibration scenario that existed in the historical data.
The input DataFrame has already had Stage-1 point predictions attached to it. The function adds three derived columns: date extracted from the timestamp, hour_of_day extracted from the timestamp, and error which is actual minus Stage-1 prediction for each row.
It then enters a double loop. The outer loop iterates over every unique combination of plant and date. For a fleet of 20 plants observed for two months that is around 1200 (plant, date) groups. The inner loop iterates over every possible split point from 1 to n-1 where n is the number of hours of data available for that plant on that day. A split point of 6 means we are simulating the situation where it is 6am, we have actual readings for hours 0 through 5, and we want to build training rows for correcting the forecast for hours 6 onward.
For each split point, it takes the elapsed rows (everything before the split), restricts to the last 6 of them, and computes two summary statistics from their error values: the mean error and the standard deviation of the error. The mean captures whether Stage-1 has been systematically over or underpredicting. The standard deviation captures how consistent or volatile that bias has been. These two numbers represent everything Stage-2 knows about this plant's behaviour so far today.
For every remaining hour after the split point, it creates one training row. That row contains the two residual summary statistics, the hour of day of the future hour being corrected, the CMF or power curve fraction at that future hour (the physics signal at the time we are trying to correct), the five asset metadata features that identify the plant, and the target variable which is the actual Stage-1 error at that future hour.
After all loops complete, the accumulated list of dictionaries is converted to a DataFrame. X2 is the subset containing only the 10 Stage-2 feature columns. y2 is the target error series. Both are returned.
The reason this function generates so many rows is that it is being thorough: every historical hour from which actuals were available is used to generate a training row for every subsequent hour in the same day. This maximises the amount of training signal for Stage-2 and ensures it has seen many different configurations of morning error history and future correction targets.
train_stage2(X2_train, y2_train, X2_val, y2_val)
Trains the Stage-2 residual corrector using the same LightGBM setup as Stage-1. The target variable here is the Stage-1 error (actual minus Stage-1 prediction) rather than the raw generation, so the model is learning to predict how much Stage-1 will be wrong given the morning's evidence. The same early stopping and logging callbacks are used. Returns the fitted LightGBM model.
predict_stage2(stage2_model, mean_recent_error, std_recent_error, hour_of_day, CMF, power_curve_fraction, capacity_mw, lat_sin, lat_cos, lon_sin, lon_cos)
A thin inference wrapper around the Stage-2 model. It accepts all 10 Stage-2 features as individual scalar arguments, assembles them into a single-row pandas DataFrame with the column names matching _STAGE2_FEATURES, calls .predict(), and returns the result as a Python float. The scalar return is a predicted error correction in MW. If the model returns -6.3, that means Stage-1 is expected to overpredict by 6.3 MW at this hour for this plant, so the final forecast will subtract 6.3 from the Stage-1 prediction.
intraday_update(stage1_model, stage2_model, day_df, cutoff_hour)
The top-level inference function for the intra-day use case. It receives a full day's data for all plants and a cutoff hour, and produces corrected forecasts for every plant for every hour from the cutoff onward.
It adds the hour_of_day column and then loops over each plant. For each plant it runs the full 24-hour Stage-1 forecast by calling transform and then predict_stage1 with return_pis=True, attaching the P50, P10, and P90 arrays back onto the plant's DataFrame. It splits the day into elapsed rows (before the cutoff) and future rows (at or after the cutoff).
From the elapsed rows it computes the mean and standard deviation of recent Stage-1 errors, using the same last-6-hours logic as the training data builder. If there are no elapsed rows (cutoff is hour 0) it defaults both statistics to zero.
Then for each future hour it calls predict_stage2 to get the scalar correction and appends a result dictionary containing the plant ID, hour of day, the raw Stage-1 P50/P10/P90, the correction amount, the corrected final P50 (s1_pred + correction), the corrected final P10 (p10 + correction), the corrected final P90 (p90 + correction), and the actual value if known. Applying the same correction to all three bounds shifts the entire interval rigidly, preserving the interval width while re-centering the distribution on the corrected point estimate.
Returns a DataFrame with one row per plant per future hour.
get_forecast(stage1_model, stage2_model, current_features_df, recent_actuals_df=None)
The public-facing inference entry point designed for deployment. A grid operator would call this function at any point during the day to get a complete probabilistic forecast.
It adds the hour_of_day column from the timestamp, runs transform to get the feature matrix, and calls predict_stage1 with return_pis=True to get P50, P10, and P90 for every (plant, hour) row in the input. These are attached to the DataFrame.
If both stage2_model and recent_actuals_df are provided, it computes Stage-2 corrections. It tries to run Stage-1 predictions on the recent actuals DataFrame to compute elapsed errors; if the actuals DataFrame does not contain the full feature set needed for Stage-1 inference it falls back to treating errors as zero. It then groups by plant, takes the last 6 hours of errors per plant, and computes the mean and standard deviation for each plant. It iterates over every row in the forecast DataFrame, looks up that plant's error summary, calls predict_stage2, and accumulates corrections. Finally it adds the correction array to all three of P50, P10, and P90.
Returns a clean DataFrame with columns: plant_id, hour, p50, p10, p90.
save_model(model, path) and load_model(path)
Thin wrappers around joblib.dump and joblib.load. Joblib handles serialisation of scikit-learn compatible objects including both LightGBM regressors and MAPIE wrappers. The saved pickle file contains the complete fitted model state including the calibration scores in the case of the MAPIE object.
The final two lines define train and predict as aliases for train_stage1 and predict_stage1, preserving backward compatibility with any external code that imported the Day-2 names.

evaluation.py
nMAE(y_true, y_pred, capacity)
Computes fleet-normalised Mean Absolute Error. It converts both inputs to numpy arrays, takes the element-wise absolute difference, averages those differences, and divides by the total fleet capacity. The result is a dimensionless fraction: a value of 0.05 means the model's average error is 5% of the fleet's maximum possible output. Dividing by capacity makes this metric comparable across fleets of different sizes.
nRMSE(y_true, y_pred, capacity)
The same normalisation applied to RMSE. It squares the differences, averages them, takes the square root, and divides by capacity. RMSE penalises large errors more than MAE because squaring amplifies outliers. Comparing nMAE and nRMSE for the same model tells you about the distribution of errors: if nRMSE is much larger than nMAE, the model is making a few very large mistakes rather than consistent moderate ones.
CRPS_stub(y_true, p10, p90)
A placeholder for the Continuous Ranked Probability Score, which is the proper scoring rule for probabilistic forecasts. Currently it computes interval coverage: the fraction of test samples where the actual falls between P10 and P90. It returns a scalar between 0 and 1. For a well-calibrated 80% prediction interval this should be approximately 0.80. The comment says it will be replaced with a proper CRPS implementation on Day 4 using MAPIE's quantile outputs.
evaluate(y_true, y_pred, plant_capacities)
An orchestration wrapper that takes raw arrays and a dictionary mapping plant IDs to their capacity in MW, computes total capacity, and returns a dictionary with two keys: nMAE_fleet and nRMSE_fleet. Useful for getting both metrics in one call.
compare_stages(y_true, s1_preds, s2_preds, plant_capacities)
Takes actuals and predictions from both stages and produces a side-by-side comparison dictionary. It computes the full evaluation dictionary for each stage, then computes the absolute and relative improvement in nMAE and nRMSE that Stage-2 achieves over Stage-1. The delta values are positive when Stage-2 is better (lower error). The pct_improvement_nMAE key gives the percentage reduction in normalised MAE attributable to the Stage-2 correction.

main.py
Module-level setup
Imports all the components and sets _HERE to the directory containing main.py. _DEFAULT_CSV is the path to the feature matrix relative to the script location. _OUT_DIR is the artefacts directory where plots are saved, and os.makedirs with exist_ok=True creates it if it does not already exist. matplotlib.use('Agg') sets the headless backend so matplotlib can save PNG files without needing a display.
_cap_map(df)
A one-liner helper that groups the DataFrame by plant_id, takes the first value of capacity_mw for each plant, and returns a dictionary mapping plant ID to its capacity. Used wherever the normalisation denominator needs to be computed.
_total_cap(cap)
Takes the capacity map dictionary and sums all the values. Returns 1.0 if the dictionary is empty to avoid division by zero. This is the denominator for all normalised metrics.
_season(month)
A lookup dictionary that maps a month integer (1-12) to a season string. December, January, and February are Winter. March through May are Spring. June through August are Summer. September through November are Autumn. Used in evaluate_coverage to group the test set by season.
train_and_eval_stage1(train_df, calib_df, val_df, test_df)
Orchestrates Stage-1 training and evaluation. It calls transform on all four splits to produce feature matrices and target arrays. It calls train_stage1 with all six of the required arrays (train, calib, and val sets). After training it calls predict_stage1 without return_pis to get just the P50 point forecasts on the test set, computes and prints the test nMAE and nRMSE, and returns the model, the test predictions, the test actuals, and the test feature matrix.
evaluate_coverage(s1_model, test_df, out_dir)
Runs the MAPIE coverage verification. It calls transform on the test DataFrame and then predict_stage1 with return_pis=True to get P50, P10, and P90 for every row. It creates a boolean array covered that is True wherever the actual generation falls between P10 and P90. The overall coverage is the mean of that array; for a correctly calibrated 80% interval it should be near 0.80.
It then attaches the covered array and a derived season column to a copy of the test DataFrame. It groups by plant_id and computes mean coverage per plant, sorts the plants by coverage for visual clarity, and generates a horizontal bar chart where each bar represents one plant's coverage, a dashed red line marks the 80% target, and a solid gold line marks the overall empirical coverage. The chart is saved to disk.
It performs the same grouping by season using the four-element season ordering (Spring, Summer, Autumn, Winter) for consistent x-axis layout, generates a second bar chart with the same reference lines, and saves that too. Both plots are printed to stdout with their file paths.
prepare_stage2_data(s1_model, df_slice, label)
A helper used twice: once with the validation DataFrame to build Stage-2 training data, and once with the test DataFrame to build Stage-2 validation data. It calls transform and predict_stage1 on the slice to get Stage-1 point predictions. It then selects only the columns that build_stage2_training_data needs, attaches the s1_pred column, and calls that function. Prints the number of rows in the resulting Stage-2 dataset. Returns X2 and y2.
The reason Stage-2 is trained on val-set Stage-1 predictions is that Stage-1 has already seen the training data during its own training, so its errors on the training set are artificially small. The validation set is genuinely unseen by Stage-1, so the errors there reflect how Stage-1 will actually behave in deployment. Stage-2 must learn from realistic errors.
train_and_eval_stage2(s1_model, val_df, test_df)
Calls prepare_stage2_data twice to build the Stage-2 training and validation datasets, then calls train_stage2 with those datasets. Returns the fitted Stage-2 model.
eval_stage2_full(s1_model, s2_model, test_df)
Validates that Stage-2 actually improves afternoon forecasts. It adds a date column to the test DataFrame and then loops over every (plant, date) combination. For each day it calls intraday_update with cutoff at noon, takes only the rows at hour 12 and later, drops any rows where the actual is not available, and accumulates the absolute errors for both Stage-1 and Stage-2 predictions. After the loop it divides the mean errors by total capacity to get normalised metrics, computes the percentage improvement, and prints all three numbers.
run(data_path)
The top-level orchestration function. It loads the data, splits it into four windows, runs Stage-1 training and evaluation, runs coverage evaluation and saves the plots, runs Stage-2 training, runs the intra-day evaluation, saves both model files to the script directory, and returns both models. This is the function you would call from a notebook or integration test in addition to the command-line entry point.
if __name__ == '__main__' block
Parses the --data command-line argument with the default CSV path as the fallback. Checks that the file exists and exits with an error message if not. Then calls run().
